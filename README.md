# Goldberg–Palatini bootstrap: symbolic supplementary material

This material accompanies `bootstrap_article_v2.tex`. It reconstructs the first-order Goldberg–Palatini action from prescribed Noether identities and checks its second-order quadratic and cubic Lagrangians against Capper, Leibbrandt and Ramón Medrano (CLM), *Physical Review D* **8**, 4320 (1973), DOI: [10.1103/PhysRevD.8.4320](https://doi.org/10.1103/PhysRevD.8.4320).

## Files and scope

| File | Purpose |
| --- | --- |
| `Goldberg_Palatini_Bootstrap_en.nb` | FeynCalc construction of tensor bases and projected Noether identities, solution of the first-order bootstrap, kernel checks, and export. |
| `Goldberg_Palatini_Bootstrap_kernels.wl` | Package-independent **data** exported by the bootstrap notebook: normalized kernels and their conventions. This is not a standalone reproduction script. |
| `Goldberg_Palatini_Cubic_CLM.nb` | xAct/xTras derivation of the inverse of M0, elimination of the linear connection, and quadratic and cubic comparisons with CLM. |

In the working project, these three files are under `Relatorio_IC_V13092026/Relatorio_IC_update/Relatório_IC/`, relative to the project root. This README is maintained in `artigo_bootstrap/`.

For distribution, place this README and the approved supplementary files together in one directory. In particular, keep the bootstrap notebook, its exported data, and the CLM notebook side by side: their export/import uses `NotebookDirectory[]`.

The CLM calculation derives the inverse here; `FirstOrderG_RiemannG.nb` is not a dependency. Backup notebooks (`_old_`, `_before_`), private logs, and the numerical Python plane-wave checks are not part of the supplementary workflow.

## Software

The current supported workflow uses the Mathematica notebook interface:

- Mathematica with FeynCalc for `Goldberg_Palatini_Bootstrap_en.nb`.
- Mathematica with xAct, including xTensor, xPerm and xTras, for the CLM notebook.

Install the packages according to their official instructions: [FeynCalc](https://feyncalc.github.io/), [xAct](https://www.xact.es/), and [xTras](https://www.xact.es/xTras/).

The author's saved kernel export records Mathematica 13.3.1 on macOS ARM and FeynCalc 10.1.0. Saved CLM package output records xTensor 1.2.0, xPerm 1.2.3, xTras 1.4.2 and SymManipulator 0.9.5. The CLM input sequence was also evaluated in a separate Mathematica 15.0.0 kernel with all final residuals zero. These observations are not a claim of compatibility with every version. Record `$Version` and package versions when preparing the final release.

## Evaluation order

### 1. First-order bootstrap

1. Save the notebook in the supplementary directory and open it in Mathematica.
2. Start a fresh kernel and evaluate the active input cells in order. Keep `Nd` symbolic.
3. Leave commented diagnostics inactive unless deliberately running them separately. In particular, the W34 diagnostic at `Nd = 4` is not part of the generic-dimension workflow.
4. Inspect the coefficient solution and the kernel checks, including the cell tagged `FullCubicKernelCheck`.
5. Evaluate the final export cell. It writes `Goldberg_Palatini_Bootstrap_kernels.wl` beside the notebook and checks that it can be read back exactly.
6. Save the notebook and its outputs.

The export success message is:

```text
Bootstrap kernels exported and read back successfully: Goldberg_Palatini_Bootstrap_kernels.wl
```

Export success verifies serialization, not the preceding bootstrap derivation. Distribute data generated by the same notebook version included in the release.

Expected first-order results:

- Kernel-basis sizes: **4, 6, 5, 16** (31 coefficients in total).
- Projection-set sizes: **3, 6, 7, 23, 20, 95**, with the domain and momentum specialization stated in the paper. These counts do not imply independence in every dimension.
- One overall normalization remains. With `cGG = 1/(Nd - 1)`, the nonzero coefficients in the notebook's basis order are `bhG = -1`, `aGG = -1`, `cGG = 1/(Nd - 1)`, `v1 = -1`, and `v7 = 1/(Nd - 1)`.
- `fullCubicKernelResidual` is **0**. This checks the complete first-order phi-G-G kernel, not the second-order CLM vertex.

The 95-element W34 projection calculation may be the most expensive stage. Reliable runtime and peak-memory measurements have not yet been recorded for the release.

### 2. Second-order comparison with CLM

1. Quit the bootstrap kernel, or assign the CLM notebook a separate fresh kernel using **Evaluation → Notebook's Kernel**. Merely opening another notebook does not isolate its kernel.
2. Open `Goldberg_Palatini_Cubic_CLM.nb` and evaluate its input cells in order.
3. Confirm that the exported data load without unresolved conversion functions or FeynCalc objects.
4. Inspect the inverse and connection checks, the quadratic boundary-term check, and the cubic residual.
5. Confirm `allChecksPassed` is **True**, then save the outputs.

The flat-background setup check should return:

```mathematica
{True, True, True, 0, 0}
```

The final residuals should be:

| Result | Expected value |
| --- | --- |
| `inverseChecks` | `{0, 0}` |
| `g0Check` | `0` |
| `clmQuadraticCheck` | `0` |
| `quadraticBoundaryCheck` | `0` |
| `clmCubicResidual` | `0` |
| `allChecksPassed` | `True` |

The final message is:

```text
PASS: the quadratic and cubic Lagrangians agree with CLM, after accounting for the overall normalization and the explicit quadratic total derivative.
```

An unevaluated symbol is not a successful residual. The aggregate PASS concerns the listed checks; it does not certify an independent bootstrap rerun or a momentum-space vertex extraction.

## Conventions and interpretation

The comparison uses the normalization of Eq. (5.1) **as written**, before the optional multiplication of the whole action by 1/2 discussed afterward. The first-order bootstrap strips the coupling; the CLM notebook restores symbolic kappa in the cubic term.

The metric and indices are abstract. The export uses ``GPBootstrapData`Eta[i,j]`` to denote a metric between free index slots, not numerical components. The six slots are `(lambda, mu, nu, rho, sigma, tau)`; the eight slots are `(mu, nu, lambda, alpha, beta, rho, sigma, tau)`. xAct raises and lowers indices with the background metric `eta`.

`CD` is the compatible derivative of the flat background, so it annihilates `eta`. In Cartesian coordinates it equals the paper's partial derivative. xAct's `PD` is a separate derivative and is not automatically identified with `CD`.

The bootstrap basis is used in generic dimension d >= 4. The derived inverse has a pole at d = 2. No gauge fixing or field equations for phi are used in the CLM comparison.

The nonlinear identities are solved with the field momenta identified, as described in Sections IV and VI. Every solution for arbitrary momenta also solves this specialized system. The specialized solution space is one-dimensional, and it contains the nonzero Goldberg–Palatini action, which is invariant for arbitrary momenta under the prescribed transformations. Thus the two solution spaces coincide within the stated ansatz. This distribution does not include a separate generic-momentum W31 calculation or claim a direct computational verification of all identities at arbitrary momenta.

CLM uses the opposite Ricci-tensor sign and an action prefactor 2/K², whereas the unrescaled bootstrap action has prefactor 1/kappa². With K = kappa and CLM's coupling-stripped coefficients, the checks establish:

\[
\mathcal L^{(2)}+\tfrac12\mathcal L^{\mathrm{CLM}}_{(2)}=\partial_aJ^a,
\qquad
\mathcal L^{(3)}+\tfrac{\kappa}{2}\mathcal L^{\mathrm{CLM}}_{(3)}=0,
\]

\[
J^a=\tfrac12\bigl(\phi^{bc}\partial_c\phi^a{}_b
-\phi^{ab}\partial_c\phi^c{}_b\bigr).
\]

The quadratic actions agree when the boundary contribution vanishes. The cubic equality is local and requires no integration by parts. The relative factor is not a physical assignment kappa = −2 or a Fourier i² effect.

The transcription of CLM Eq. (2.16) uses the index-consistent contraction `phi_(mu tau) phi_(mu sigma),lambda phi_(lambda tau),sigma` for the first term in its second group; the printed scan has inconsistent index multiplicities there. This choice is disclosed in the notebook and manuscript. The calculation compares CLM Eqs. (2.10) and (2.16), not a separate transcription of Eq. (2.17).

## Command-line and free-Engine status

Complete public `.wls` reproduction drivers are **not yet supplied or validated**. The kernel-data `.wl` file does not replace them. Preparing drivers requires adapting frontend-dependent operations, replacing output-history references such as `%`, handling portable paths, and checking all expected results with appropriate exit codes.

Running without a paid Mathematica license would require a separately tested Wolfram Engine workflow and compliance with the terms of its free license. It is not execution without a license. See the [official terms](https://www.wolfram.com/legal/terms/wolfram-engine.html). Tests with an installed Mathematica kernel do not establish validation with the freely licensed Engine distribution.

Python/SymPy implementations of basis generation and Gram determinants exist in the working project. They are optional, partial independent checks, not an automatic translation of the notebooks or a complete Python implementation of the bootstrap and CLM comparison.
